# Administrator Routes

`/admin/login` is public and exposes email/password sign-in only. The `(protected)` route group keeps URLs stable while applying `requireAdmin()` to the dashboard and any published inquiry pages. `/admin/dashboard` is a database-backed analytics report with protected CSV links. While inquiry publication is hidden, its navigation, metric, recent-row query/table, export, direct page, and mutation actions are absent or not found. Once published, `/admin/inquiries` is a 20-row paginated private-data view with allowlisted filters, status-only updates, and an explicitly confirmed exact-record deletion path.

`src/proxy.ts` matches only `/admin/*`, refreshes/verifies Supabase cookies, applies private/no-store caching, and redirects unauthenticated protected requests. The protected layout repeats the authoritative identity and `admin_profiles` authorization checks on the server. Proxy checks must never replace server/data authorization.

All administrator routes are marked `noindex`. Errors are non-revealing, no public registration exists, and no credential is stored in route code. Dashboard, inquiry, action, and export reads never import the service-role client; authenticated clients, base-table RLS, and `SECURITY INVOKER` functions enforce access together.

Dashboard query parameters are untrusted. Invalid, reversed, future, or longer-than-366-day custom ranges render an inline validation state and do not query the database. All successful cards, charts, and recent tables use the same start-inclusive/end-exclusive interval.

The dashboard operational panel is server-evaluated and protected by the same layout. It differentiates the collection switch, server write-configuration presence, authenticated reporting reachability, global newest analytics timestamps, and the selected range's empty state. Its manual refresh uses Next.js route refresh; it never exposes environment values or reads through the service-role client.

Inquiry Server Actions must be treated as public endpoints. They first enforce the server-only publication boundary, then repeat `requireAdmin()`. Status changes validate the bound UUID and allowlisted status, update only `status`, revalidate fixed admin paths, and redirect only to fixed notices. Deletion separately validates one UUID plus an explicit confirmation value, then invokes only `delete_contact_inquiry(uuid)` through the signed-in request-scoped client. That database function independently checks the approved-admin helper and can delete at most one primary-key row; there is no direct browser-role table DELETE or bulk-delete action. The CSV handler lives under the proxy matcher but repeats authorization, publication, type/date validation, row limits, and private download headers internally.

When inquiry publication is visible, the inquiry operational panel reports only the server collection-switch state, write-configuration presence, authenticated RLS reporting reachability, newest stored timestamp, and refresh time. It never displays a configuration value or uses the privileged backend client to read records. The page reminds the approved operator to check daily because this site sends no automatic inquiry notification or reply.
